# Projets (PR 1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal :** Ajouter les projets de développement (privés) avec leurs tâches typées (tâche, bug, amélioration), une page par projet et une section « Projets » dans la barre latérale.

**Architecture :** Deux nouvelles tables (`projects`, `project_tasks`) indépendantes des clients, deux routeurs FastAPI (`/projects`, `/project-tasks`) qui réutilisent `repository.owned` pour l'isolation par compte et `recurrence.py` pour la récurrence. Côté Vue : un store Pinia, deux vues (`/projets`, `/projets/:id`) et une entrée de barre latérale.

**Tech Stack :** FastAPI, SQLAlchemy, Alembic, pytest ; Vue 3, Pinia, Tailwind, vitest.

## Global Constraints

- Spec : `docs/superpowers/specs/2026-10-29-projets-design.md`.
- Tout reste derrière la connexion dans cette PR ; `is_public` existe mais n'est exposé qu'à la PR 2.
- Ressource d'un autre compte → **404**, pas 403 (`repository.get_owned_or_404`).
- Archivage plutôt que suppression (`archived_at`), cascade projet → tâches avec le même horodatage.
- Migrations Alembic numérotées à la suite (`0008`), le test `test_migrations_match_models` doit rester vert.
- Ruff (ligne 110) et Prettier propres ; messages et commentaires en français.
- Écart assumé par rapport à la spec : commentaires et historique des tâches de projet sont reportés à la PR 3 (avec les checklists et l'onglet Activité). Cette PR livre statut, priorité, type, échéance, récurrence, archivage.
