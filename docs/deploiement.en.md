# Deploying KeepPace

[🇫🇷 Français](deploiement.md) · 🇬🇧 English

Two ways to put KeepPace online:

- **on your own server**, with `docker-compose.prod.yml` (see the
  [README](../README.en.md#production)): this is the option for real data;
- **as a public demo** on [Render](https://render.com), with the
  [`render.yaml`](../render.yaml) blueprint described below.

## Public demo on Render

[![Deploy to Render](https://render.com/images/deploy-to-render-button.svg)](https://render.com/deploy?repo=https://github.com/pmau-d/KeepPace)

The blueprint creates three resources:

| Resource       | Purpose                                                              |
| -------------- | -------------------------------------------------------------------- |
| `keeppace-db`  | PostgreSQL database                                                  |
| `keeppace-api` | API (`backend/Dockerfile` image): migrations on start-up, `/health`  |
| `keeppace`     | Frontend (`frontend/Dockerfile` image): nginx serves the application and proxies `/api` to the API |

Demo mode is enabled (`DEMO_MODE=true`): on first start, the API creates the
**demo@example.com** account (password `demo-keeppace-2026`, configurable with
`DEMO_PASSWORD`) filled with fictitious data. Sign-ups are closed
(`ALLOW_REGISTRATION=false`) and `SECRET_KEY` is generated by Render.

### Steps

1. Create a Render account and click the button above (or **New →
   Blueprint**, then choose this repository or your fork).
2. Confirm the three proposed resources: Render builds both images and creates
   the database.
3. Open the URL of the `keeppace` service and log in with the demo account.

### Good to know

- **Free plan**: services go to sleep after a period of inactivity (slow first
  load) and the free database has a limited lifetime. Move to a paid plan for a
  permanent demo.
- **Demo data only**: `DEMO_MODE` publishes an account whose password is
  known. Never enable it for real data.
- **Resetting the demo**: delete and recreate the `keeppace-db` database; the
  demo account is recreated when the API restarts.
- **E-mail digest**: disabled; it requires an SMTP server (`DIGEST_ENABLED`,
  `SMTP_*`, `APP_URL`, see the README).

## Other hosts

Both images are self-contained; you only need to provide:

| Image            | Variables                                                      |
| ---------------- | -------------------------------------------------------------- |
| API (`backend/`) | `ENVIRONMENT=production`, `DATABASE_URL`, `SECRET_KEY` (32 characters min.); port 8000 |
| Frontend (`frontend/`) | `BACKEND_URL`: API host and port as seen from the frontend (e.g. `api.internal:8000`); port 80 |

The PostgreSQL URL can use the `postgres://`, `postgresql://` or
`postgresql+psycopg://` format. Put an HTTPS terminator in front of the
frontend: the session cookie is `Secure` in production.
